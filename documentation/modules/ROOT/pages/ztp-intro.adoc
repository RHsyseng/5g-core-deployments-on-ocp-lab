= Introduction to Zero Touch Provisioning (ZTP)
include::_attributes.adoc[]
:profile: 5g-core-lab

Telco Core deployments typically involve managing a *handful of multi-node OpenShift clusters* across regions or central sites, not the massive edge footprint of RAN. Each cluster must run with high availability, and operators need *aligned, consistent configuration* across the fleet so that provisioning, upgrades, and day-2 changes remain predictable and auditable.

*GitOps Zero Touch Provisioning (ZTP)* addresses this by storing the desired state of every cluster—installation and ongoing configuration—in Git and reconciling it automatically from a *central hub*. ZTP uses declarative specifications for bare-metal provisioning and day-2 configuration following GitOps practices. *Red Hat Advanced Cluster Management (RHACM)* automates initial deployment and configuration ("zero touch") and provides *central cluster management and lifecycle management (LCM)* for the managed clusters.

[#what-is-ztp]
== What is ZTP?

ZTP is a project to deploy and deliver OpenShift in a hub-and-spoke architecture (in a relation of 1-N), where a single hub cluster manages many spoke clusters. The hub and spokes run OpenShift; the hub additionally manages, deploys, and controls the lifecycle of the spokes using Red Hat Advanced Cluster Management (RHACM).

Then, hub clusters running RHACM apply core network policies from predefined custom resources (CRs) and provision and deploy the spoke clusters using multiple products. Those components are part of what is called the Telco {core-rds-link}[Core Reference Design Specification (RDS)]. The Core RDS captures the recommended, tested, and supported configurations to get reliable and repeatable performance for clusters running the telco core profile, supporting large-scale applications such as control plane functions (signaling, aggregation, session border controller) and centralized data plane functions like 5G User Plane Functions (UPF).

We will take a closer look at these components in the link:ztp-at-scale.html[Hub Management Components] section.

IMPORTANT: ZTP can operate in both connected and disconnected environments. In the connected case, clusters have direct access to the Internet. The disconnected case, which uses a private registry accessible within the customer's network, is the most common in the telecom environment, and will be used in this lab.

ZTP provides support for deploying single node clusters, compact or three node clusters, and standard OpenShift clusters. This includes the installation of OpenShift and deployment of the cluster at scale. In this lab, we will focus on Multi-Node OpenShift (MNO) clusters, which is the reference topology for Telco Core deployments, as introduced in link:mno-intro.html[Introduction to Multi-Node OpenShift (MNO)].
